# Donor Source Provenance Gate

This directory is the Stage 0A provenance record for Fresnica Mobile.

Audited donor snapshots:

- Stellar: `bd0f4540b2496a57314e4e29bc6fcf8ff691b60f`
- Xaman-App: `01e2538b08efa2c960233911fad02633f31ce6cd`

Both donor trees carry the XRPL Labs CUSTOM dual license. File presence in the Stellar derivative tree is not proof that Fresnica may directly migrate that source.

Default implementation policy:

- product behavior, protocol inputs/outputs, errors and acceptance criteria may be studied;
- implementation structure, expressions, comments, tests and resources are rewritten clean-room;
- a direct migration requires file-level independent-rights evidence plus an explicit approval record;
- absence of the same path in the audited Xaman commit is not proof of independent ownership.

`donor-source-ledger.tsv` is generated by `node scripts/audit-donor-provenance.mjs` and is the file-level evidence index. It proves which audited blobs were identical or different at the two pinned snapshots; it is not a legal conclusion and cannot prove independent authorship by itself.

## Clean-room working rule

Before implementing behavior learned from a donor surface:

1. Record the user-visible flow, protocol inputs/outputs, state transitions, security invariants and acceptance cases in the product trace row or a linked behavior specification.
2. The implementation is written from that specification and Fresnica contracts, without donor source, tests, comments or local resources being used as a coding template.
3. Record donor paths only as audit evidence in the PR. Do not paste donor excerpts into implementation issues, code review or generated source.
4. Prefer a separate behavior reviewer and implementer. When staffing does not allow separation, keep a contemporaneous behavior specification and require an independent implementation review before merge.
5. A direct migration remains prohibited unless a separate rights review supplies file-level history, author/rightsholder confirmation, dependency licensing and an explicit approval record.

Regenerate the ledger only against the audited commits recorded above, or update this README and review the resulting ledger diff in the same PR. Moving donor `HEAD` must never silently redefine the audit baseline.
