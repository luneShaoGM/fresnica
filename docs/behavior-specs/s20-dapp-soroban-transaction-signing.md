# S20 DApp Soroban transaction signing on Stellar Testnet

Phase 2b candidate. The dApps feature owns review and uses the existing Transaction and Signing capabilities. Clean-room adaptation of the Freighter-compatible transaction request. Blend UI and Stellar SDK inputs establish protocol behavior.

- A connected web page may request `signTransaction` using its original assembled envelope. Fresnica reviews one unsigned Testnet contract invocation, using the selected Classic G-account as the source, a finite unexpired time bound and a single source-account authorization tree. Native SDK 0.3.1 signs after fresh App Passphrase. The existing original-document reply returns the signed envelope to the page, which submits it.
- Supported intents are a standard native-token contract transfer and a single Blend v2.1 Testnet collateral supply funded with native XLM. Known contract identity, exact arguments and matching authorization root are required. A supply must authorize exactly one matching token transfer from the selected account to the reviewed pool. Other contracts or methods, extra invocations, altered arguments, fee bumps and independent address credentials are rejected. `signAuthEntry` remains deferred.
- Review shows website, network, source, contract, destination, amount, fee and transaction hash. Review and signing use the same network-bound hash and original envelope. The original session and the transaction time bound must still be valid before signing and before any result can be returned.
- Test fixture provenance: Blend UI commit `6aa28273640a86d62cb07680cdf482d9c88d69f9` transaction construction for 1 XLM on its v2.1 Testnet pool, simulated against Stellar Testnet RPC at ledger 5948510. This is unsigned public test data. Separate native SDK probes signed the same fixture on Android and iOS simulators. Native app acceptance requires the Blend page to request, sign and submit a fresh envelope, then read a changed position on both platforms.
