# S20 DApp Soroban transaction signing on Stellar Testnet

Phase 2b candidate. The dApps feature owns review and uses the existing Transaction and Signing capabilities. Clean-room adaptation of the Freighter-compatible transaction request. Blend UI and Stellar SDK inputs establish protocol behavior. [Upstream Protected Software Transaction Signing](https://github.com/Fresnica/fresnica/blob/2750d3cb44f58f3c09198fbfe1585dfb7d9aad48/docs/platforms/mobile/protected-software-signing.md) defines the native envelope contract, which is checked through the canonical adapter manifest on both native gates.

- A connected web page may request `signTransaction` using its original assembled envelope. Fresnica reviews one unsigned Testnet contract invocation, using the selected Classic G-account as the source, a finite unexpired time bound and a single source-account authorization tree. Native SDK 0.3.1 signs after fresh App Passphrase. The existing original-document reply returns the signed envelope to the page, which submits it.
- Supported intents are a standard Stellar Asset Contract transfer and a single Blend v2.1 Testnet collateral supply funded with native XLM. Known contract identity, exact arguments and matching authorization root are required. A supply must authorize exactly one matching token transfer from the selected account to the reviewed pool. Other contract types or methods, extra invocations, altered arguments, fee bumps and independent address credentials are rejected. `signAuthEntry` remains deferred.
- Issued-asset transfers require a writable Classic trustline key for the source or recipient in the exact transaction footprint. The wallet decodes the asset code and issuer, derives the canonical Stellar Asset Contract address for the selected network, and checks that it equals the invoked contract. The same key must round-trip as canonical XDR. Read-only keys, unrelated accounts, alternate issuers and contracts without a matching identity fail closed. The review shows the full issuer. This uses the existing single source-account authorization path and performs no new RPC reads.
- Review shows website, network, source, contract, destination, amount, fee and transaction hash. Review and signing use the same network-bound hash and original envelope. The original session and the transaction time bound must still be valid before signing and before any result can be returned. Review closes at the earlier of the envelope deadline and the bridge deadline without changing the original reply handle.
- Test fixture provenance: Blend UI commit `6aa28273640a86d62cb07680cdf482d9c88d69f9` transaction construction for 1 XLM on its v2.1 Testnet pool, simulated against Stellar Testnet RPC at ledger 5948510. This is unsigned public test data. Separate native SDK probes signed the same fixture on Android and iOS simulators. Native app acceptance uses a fresh transaction generated by the real Blend page.
- On rejection, expiry or unsupported requests, the bridge includes the Freighter `apiError` field as well as the existing error string, so callers do not attempt to submit an empty signed envelope.

## Testnet simulator acceptance

At Mobile commit `d34bf967827b1e0549a44bdacf098de9dae49d77`, each simulator used a separate disposable wallet in a fixed-Testnet test runtime. The app opened the official Blend XLM Supply route in its controlled browser, approved one-time wallet access, presented the real page's 1 XLM collateral supply, signed after fresh App Passphrase and returned the signed envelope to Blend. The live v2.1 Dashboard showed a price-oracle banner, so the tests entered the official Supply route directly. Blend displayed successful submission on both simulators. Independent Stellar RPC confirmed the exact hashes and nonzero collateral positions.
