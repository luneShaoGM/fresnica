# Shared bottom-sheet dismissal (2026-11-20)

- Decision: **Adapt** Fresnica's existing `AppModal` sheet implementation. Existing `BottomSheet` consumers now delegate to the same header/handle drag-dismiss surface rather than maintaining a separate native `Modal` implementation. Phase 0 / Stage 0A applies. This presentation-only change supports S06/S13/S15/S22 and the shared UI kit. Clean-room Fresnica implementation; no donor code copied.
- Scope: Activity filters, Add Asset, asset picker, contacts and recipient surfaces, dApp catalog/URL/connection/sign review sheets use the shared close mechanics without changing each feature's flow or local state. Preserve 88% sheet height, vertical content scrollability, safe-area bottom padding, cancel/reject callbacks, backdrop close, Android Back, and accessibility escape.
- The full 88% sheet shell, drag-handle region, content and bottom safe-area inset use the same semantic `background` color, including dark/custom appearance. Other `AppModal` consumers keep their default `surface` color. The generic drag-handle accessibility label uses the existing three-language dictionaries through `common.dragDownToClose`, not the Actions-specific label.
- A **deliberate downward pull from the visible drag handle** dismisses the sheet; short pulls rebound, and upward/horizontal moves do not dismiss. The handle is outside child scroll surfaces. Content-scroll-to-top continuous handoff is **not** claimed for these `BottomSheet` consumers; Home XLM/token details already use the separately validated native `formSheet` pathway (see `s06-asset-sheets.md`).
- Centered dialogs and full-screen transaction/approval routes retain their previous presentation; this does not relax authorization, account/network partitioning, exact-XDR, signing, lifecycle, or recovery rules. In particular, dApp sign dismiss still invokes reject and clears any staged secure input.
- Validation scope: shared-component structure and close forwarding, Activity draft/apply isolation and existing contacts/assets/dApp tests, TypeScript, lint/style, architecture, locale and provenance. Automated tests cannot establish native touch behavior in Android/iOS product flows. Native handle swipe, scroll collision, short drag, close/backdrop/Back, accessibility/dynamic-font and wallet authorization rejection paths remain separate product acceptance.
