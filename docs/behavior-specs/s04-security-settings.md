# S04 Security settings

Phase 0 foundations reused; S04/S27, Adapt, clean-room from Fresnica session/privacy contracts and the owner-requested Settings controls. Feature owner: security. Application Security validates/persists policy and uses the existing SDK fresh-passphrase verifier; App composes session/native policy, platform owns window flags. No signer encryption, signing authorization, ledger or transaction changes. Existing strict Security scope remains; no donor source copied.

- Preserve protected cold/manual lock, passphrase fallback and independent OS biometrics. A persisted App-only biometric preference controls visibility and execution of the biometric unlock path; disabling it cancels old authentication through the session revision. It never affects key/signature authorization.
- Background lock choices: immediately, 30 seconds (default), 1 minute, 5 minutes. No never-lock mode. Resume uses the current validated duration; missed native backgrounds still lock conservatively. Network service handoff remains bounded by the existing separate 30-second rule. Device restart remains cold-locked.
- Public policy uses an independent security record in the existing separate settings Realm. Invalid data retains secure defaults. Presentation preferences cannot overwrite security policy. Save failure does not publish changes. All local protected signers require fresh App Passphrase for each settings Save; watch-only has no invented credential. Background/inactive/blur/unmount aborts and clears native input; stale completion cannot save. Credentials never enter React state/props/navigation/Realm.
- Android screenshot protection defaults on. Only Developer Mode exposes disabling, after a warning that capture/recording may expose wallet/recovery screens, then explicit Save and fresh passphrase where applicable. Outside Developer Mode or while locked/backgrounded, protection is forced on regardless of the saved preference. MainActivity applies FLAG_SECURE before onPause; the lifecycle-aware native module rejects disabling outside a resumed Activity. Native application failure prevents Save and forces protection on. iOS has no screenshot-disable control; the existing privacy cover is retained.
- Settings keep S03 recovery/change-passphrase routes. Fields and actions are localized and scrollable, and failure leaves a fresh-input retry available. Disabled biometrics always retain verified passphrase unlock.

Verification: automated validators, authorization/stale/save/native-failure paths, session timeout and biometric preference; real Realm independent-record reopen; Android compile/native tests and iOS build where available. Native screenshot/background transitions, biometric enrollment/cancel/lockout, dynamic text and screen-reader product acceptance are separate. Stage 9 iPhone acceptance remains deferred. No L4/release approval is implied.

SDEX/LP remains a separate PR; owner chose to wait for the upstream LP withdrawal contract rather than ship a read-only substitute. Upstream Fresnica main audited at 38e804b435be5d3c6a0400de4e79f102822cb8e0 supplies Normative SDEX and sdex-v1 vectors, but no LP withdrawal capability contract.
