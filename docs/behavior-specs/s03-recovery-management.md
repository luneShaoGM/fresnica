# S03 recovery material and protection management

Phase 0 foundations reused; S03 Adapt / clean-room from current Fresnica SDK contracts and the owner request. No donor implementation copied. Capability owns signer eligibility and all-wallet atomic rotation, app composes the global signer repository, platform owns persistence/clipboard, feature owns transient presentation. New RecoveryManagement presentation joins strict architecture scope. No aggregate L4 promotion.

- Account details and Security offer recovery material only for attached protected-software signers with complete envelopes and recorded mnemonic/secret recovery kind. Watch-only, external/hardware and pending-backup signers cannot reveal. SDK reveal receives the exact expected signer and a freshly supplied App Passphrase; output kind must match stored recovery kind. A mnemonic-backed signer exports its mnemonic, optional mnemonic passphrase, language and derivation index; it does not invent a raw private key derivation API.
- Plaintext never enters React state, render props, navigation, Realm or diagnostics. An uncontrolled native field is filled imperatively for deliberate presentation; transient references and fields are cleared on close, blur, background, unmount and after 60 seconds. Late SDK results after cancellation or inventory change cannot show. No screen can resurrect material on refocus without fresh passphrase.
- Explicit Copy exports the displayed recovery text with a warning. A dedicated native clipboard port marks it sensitive on Android, local-only with expiration on Apple, clears after 30 seconds and on native background/close, and never clears a newer unrelated clipboard value. Plaintext file/share exports are not introduced.
- Change App Passphrase consumes old/new/confirmation fields, enforces the existing 15-Unicode-scalar minimum and exact confirmation, and re-protects every protected signer across all network partitions, including hidden/shared signers. Verify all staged envelopes with the new passphrase and expected signer before committing. No plaintext is persisted. Block pending backups and unresolved submissions.
- One atomic Realm write compares the complete captured signer inventory and replaces only each protected signer's envelope/revision/update time. Staging, cancellation, identity mismatch, concurrent inventory change or persistence failure leaves every old envelope unchanged. Retire legacy System Auth key domain before committing so obsolete credentials cannot survive rotation; it is not re-enrolled under the passphrase-only signing policy. Cancellation after domain removal may require biometric-domain setup for legacy consumers but does not change any stored passphrase. App-unlock biometrics are independent.
- After successful commit, lock the App and require re-entry with the new passphrase. Never treat App unlock as signing/export authority. Raw SDK errors are not displayed or logged.

Validation must include wrong passphrase, kind/identity mismatch, cancel/late completion, shared/cross-network signers, staged failure, stale-inventory CAS, commit rollback/reopen and old/new passphrase behavior. Native clipboard expiry/background and real-device privacy/reading acceptance remain explicit separate gates.
