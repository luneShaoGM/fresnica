# LC5 Phase 3 — dApp detail and public icon candidate cache

Status: **implementation candidate**, based on `main@b68ab23f2ce00b6282cf97b2ec832bcbe6017c78` after user-merged S06 Phase 2 / PR #171. Stage 7 S14 read-only dApp owner; reference behavior: `origin/Stellar@stellar-migration` DappCatalogService (24h detail) and DappIconCacheService (7d winner / 24h failures). Decision: **Adapt** (clean-room, no donor source/artwork). Scope excludes browser/permission and claim operations.

## Scope and ownership

- The S14 production catalog from `https://dapp.fchain.io/v1` retains its existing network-scoped Realm cache and foreground/online gating. This phase **does not replace or reimplement** those validated gates.
- A catalog row can carry a strictly validated optional public `iconUrl` candidate. Unsafe/malformed **optional** icon metadata is discarded without corrupting an otherwise complete approved directory row. Listings are untrusted public descriptions, never evidence of an authenticated origin or authorization.
- An explicit catalog-row **View public details** action opens a **read-only** bottom sheet. The detail source is the fixed HTTPS FChain endpoint `/v1/dapps/{encodedIdentifier}`, not the row's launch URL. The native Phase-2 `SecureAssetFetch` transport handles text receipt (512 KiB ceiling, validated connected public IP and TLS name, no redirects). If the native transport is absent, cached detail may be shown but no new detail fetch occurs. The sheet never opens the dApp, grants wallet access, signs, or edits Recent.
- Validate source schema, active stage, exact identifier, developer name, bounded description, network-specific launch URL and sanitized optional icon URL before publishing. On malformed/empty/other-network detail responses, retain the last-good detail. Wallet account identifiers, private tokens, user navigation parameters, image bytes, permissions and transaction data cannot enter this cache. Provider-supplied public launch URL query parameters remain untrusted display text and are never executed by this read-only detail sheet.

## Durability and lifecycle

- **Realm v12** adds only the independent public `DappDetailCacheEntity` keyed by JSON exact `(networkId,appId)`. No existing Account, Signer, Pending/uncertain, Balance, History, contact, catalog, grant or token metadata entity is altered. The old v9/v10/v11 migration fixtures exclude new table names; v11→v12 migration/reopen is tested against real Realm data.
- Successful detailed metadata TTL **24 hours**, retry cooldown after failure **30 seconds**. During offline/failed refresh retain the complete last-good savedAt timestamp, mark stale and permit explicit Retry. No response from a cancelled, superseded, closed or different-network service may be committed. Invalid/unknown networks and identifiers fail closed. Corrupt cache rows are ignored, not a reason to rewrite good data.
- Icon candidates are untrusted display-only public HTTPS URLs supplied by validated catalog/detail. Order: successful previously vetted candidate first (only while its **7-day** winner TTL is active), then catalog candidate and detail candidate, deduplicated. Failed candidate cooldown **24 hours**. Persist only bounded winner/failure URL metadata in the same display record, never image bytes, cookies or account data. No automatic site favicon scraping.
- Public dApp icons are **OFF by default** and require an explicit UI opt-in that discloses contacting external image servers. All downloaded bytes pass through the already-reviewed native transport from Phase 2, and the RN UI receives a **local** `data:image/png|jpeg;base64` only; never give remote URL directly to RN Image. Native app missing the bridge hides the toggle. Icon loading happens only for the **selected detail** while the sheet is open and the route is active/online; scrolling a 500-item directory never causes bulk icon requests. The session-local image cache holds at most **24** bounded data URIs for **10 minutes**, is cleared on opt-out/retirement, and falls back to a deterministic local dApp initials icon on failure/unsupported image.
- Explicit cancellation/retirement on network switch, route blur, sheet close, offline transition and AppServices teardown: stale callbacks neither open a site nor mutate wallet permission state, and in-flight detail/icon requests are cancelled or discarded. Any cross-session/read identity is display-only and bound to the active service.

## LC5 other-consumer decisions

- **S11 Claimable current-state snapshots — DEFERRED.** Fresnica currently has claimable-create/claim/clawback **History operation evidence**, but no user-facing **live Claimable list, claimable account read/pagination, or claim authorization** consumer. Stellar's 1h current snapshot is a reference for S11 only. Reusing historical Activity records as current claimability would be incorrect; no false current-state cache or unsupported claim path is added. S11 must define live source, predicates, temporal re-derivation, max pages, account/network isolation and claim authorization before a real snapshot cache is introduced.
- **S22 Resolver/contacts — EXISTING LOCAL behavior retained; remote cache DEFERRED.** `src/capabilities/contacts/contacts.ts` supplies memo-aware exact identity resolution, and `RealmContactStore` already provides persistent contact storage, revision and subscription invalidation. Contacts are intentionally network-independent; exact address+typed memo distinction is preserved. No approved remote KYC/advisory/federation resolver API is configured in this mobile phase; therefore no speculative stale remote-identity cache, cloud trust suggestion or hidden cross-network reputation lookup is created. Any future remote resolver requires its own S22 specification, source contract, TTL, privacy gate and tests.

## Verification and boundaries

- Tests must prove exact network+app-id partition, source/schema/version/URL validation, cache freshness and retry, stale/offline process-reopen recovery with actual Realm migration, icon candidate order, default OFF and local fallback, no external image request before user opt-in, no hidden wallet permission/Recent changes, and late callback rejection on cancel/session retirement.
- Full repository `npm run check`, `npm run test:realm -- --watchman=false`, latest-head CI and independent Work Review are required before this is an approved merge candidate. JavaScript/Realm tests do not prove real iOS/Android product-flow acceptance. Native Phase-2 downloader is reused **without changing native code**; no new native network security claim or device acceptance is implied.
- Stage 9 iOS real-device System Auth cancel/retry remains explicitly deferred. No product maturity promotion solely for this cache work. User chooses whether/when to merge after exact remote HEAD Work Review (P1/P2 must be resolved).
