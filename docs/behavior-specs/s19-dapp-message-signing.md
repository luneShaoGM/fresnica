# S19 SEP-53 message signing

Phase 2b navigation and the existing SDK 0.3.1 message-signing mechanism carry this clean-room Adapt slice. The dApps feature owns the review, the dApp session validates the request and its lifetime, and SDK/Core owns SEP-53 signing. The default wire format follows official Freighter at b947b520533b2a92f3b48d52b209cc418bd539e9. Stellar at bd0f4540b2496a57314e4e29bc6fcf8ff691b60f is the behavior reference for Base64 payload bytes and signature response encoding. Existing dApps and navigation strict scopes apply.

A live verified HTTPS main-frame connection can request SUBMIT_BLOB. An explicit account or network must match the active selection. The one active signing slot is shared with transaction signing. Requests are deduplicated per document. Messages are limited to 4,096 UTF-16 code units. Blank messages, malformed UTF-16, invisible format characters and controls other than CR, LF and tab are refused. The review displays origin, address, network and the complete message as quoted text, so whitespace and escape sequences can be checked. Official Freighter sends raw text in blob, which is also the default when blobEncoding is absent. A client sending Stellar-style Base64 bytes must explicitly add blobEncoding: base64. It must send canonical padded Base64 and valid UTF-8 that round-trips byte-for-byte through the existing string-only SDK interface. The decoded text is what the user reviews and the SDK receives. There is no encoding inference from blob contents or apiVersion, and unmarked legacy Base64 is interpreted as literal text under the official Freighter contract. Binary non-UTF-8 messages require a byte-oriented SDK interface and are rejected. Neither form is normalized or pre-hashed in JavaScript.

Approval consumes a fresh App Passphrase from the existing secure input. Only the protected software signer matching the selected Classic address is eligible. Cancel sends user-declined. SDK rejection allows another passphrase entry. Document replacement, browser navigation, account/network change, permission revocation, focus loss and close invalidate approval or suppress a late completion. Successful responses carry signedBlob and signerAddress, correlated with the original Freighter message ID. Android binds the response to the original main-frame JavaScriptReplyProxy. iOS resolves the original WKScriptMessageHandlerWithReply callback. Native code allocates the one-use handle, passes it to the app outside the page payload, and drops replies for missing handles. Message signing never falls back to injecting a signature into the current document. Requests without a native reply handle cannot start signing. Stable Freighter API versions below 4 return hex and versions 4 or newer return Base64.

Android Fabric and legacy command dispatch both consume SEP-53 replies through the native handle before considering ordinary WebView messages. Invalid, missing or consumed handles must not fall back to a window/document message. A real new document retires the old handle; same-document History API navigation retains it.

iOS callbacks keep their existing 120-second lifetime. Native code supplies the expiration time outside the page payload, including through Fabric Codegen; a missing or invalid native deadline cannot provide a signable iOS handle. Expiration closes the review, clears its secure input, invalidates the signing generation and releases the session slot. Confirmation checks the deadline before consuming a passphrase, and SDK completion checks it again. Wrong-passphrase retries retain the original deadline; an expired request requires a new website request. While an earlier SDK operation is still running, a new review cannot consume a passphrase. Native Promise rejection returns a correlated unavailable error only in the original document and does not expose native diagnostic text.

Native acceptance on Android and iOS: connect a test dApp, review a UTF-8 challenge and verify its returned SEP-53 signature against the selected public key; exercise cancellation, wrong passphrase and retry, watch-only selection, navigation and account/network change.
