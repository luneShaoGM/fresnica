# S10 Stage 6 — Swap-D2b quote and unsigned transaction preview batch

Status: **larger coherent product batch**, Work exact-HEAD review required. Target source: upstream Fresnica/fresnica PR #188 Path Payment Normative contract. This is a read-only quote and unsigned-XDR review product flow, **not a user-authorized swap transaction**.

## User-facing and navigation scope

One integrated action path: eligible Classic signer account on MainTabs Actions overlay → Exchange preview → current source account asset inventory → select distinct source and destination assets, fixed-send or fixed-receive mode and amount → get quote(s) → select route / requote → explicit integer slippage bps → prepare a single unsigned Path Payment using fresh ledger base fee and live preflight → show the original selected quote and the inspected transaction's source, destination, exact issued-asset issuer identity, ordered route, both quoted amounts, mode-specific minimum receive / maximum source, fee, and separate transaction TimeBounds → Done.

The exchange route accepts **only accountId** as a navigation parameter. No secret, passphrase, original quote, prepared XDR, reviewed transaction, signing capability or pending submission enters React Navigation state. Home and Actions continue to be signer-aware. The preview shows a clear localized disclaimer that signing and broadcasting are _not_ available. The new AppServices composition exposes existing Path Payment quote/preflight/unsigned builder adapters to a dedicated read-only feature port, and does **not** pass any SDK authorization or submit function into the preview.

## Live session, recovery, exact value

- MainTabs owns the current account ID and a monotonic selectionRevision store. Successful persisted explicit switches advance the revision immediately (before React re-render), including A→B→A in a single JS tick. Committed fallback/account inventory/network updates also advance it; the store has a subscription and invalidates on unmount. Failed default-account writes never commit a new selection.
- Home's Exchange route subscribes to that store and remounts the preview when the revision changes. It captures the **original** route focus epoch with the existing createRequestRouteFocusLifetime and uses the already-reviewed captureSwapCurrentSession. Blur, unmount, hidden/deleted/changed account, complete network/passphrase rebind, repeated selections or route refocus invalidate older requests. Preview asset load, quote, prepare and review transitions check both the captured current session and an in-component generation counter before/after awaited I/O. Stale asynchronous completions cannot change a newer operation's lock.
- Swap requests explicitly use the **same Classic account for source and destination**, preserving the selected 7-decimal fixed side and full asset code/issuer identity. Quote provider and selection/expiry policy are the previously approved Swap-A/B modules; live-account/trustline/reserve preflight and protected unsigned XDR builder are the previously approved Swap-C1/C2 modules. Fee is read as the ledger base fee and reverified at prepare. No chain amount uses JavaScript floating point; bounds are delegated to BigInt Capability policy.
- Failed asset loads expose an explicit Retry, unavailable routes/expired quotes are surfaced in a localized error and can be requoted. The quote's 30-second wall/monotonic TTL is only a quote/prepare gate, while the unsigned XDR has its own transaction TimeBounds. Changing input, source/dest asset, fixed side or route requires returning through quote and prepare.
- There is no local Realm schema write, signing key disclosure, automatic submit, result success fabrication, or new recovery worker. Existing shared TransactionReconciliationCoordinator already remains responsible for pending / uncertain transaction recovery; live result and resume UI are intentionally **the following batch**, not reached through this preview.
